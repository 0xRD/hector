## In order

0. **Main window layout on macOS 26: fixed** (local session, macOS 26.6.2). The empty sidebar and the cut-off map had one cause: on macOS 26 the AppKit split views behind `.inspector` and `VSplitView` take the content's *ideal* height as a minimum, and a `List` or `Table` has the height of all its rows as ideal height. The split view grew to about 1,800 pt in a 950 pt window and was centered, so every column, sidebar included, lost its top and bottom. Connections, Persistence, Processes and Keyboard taps all had it; Blocklists, Checkup and Camera & mic did not (no inspector). Fix: `fillsSplitPane()` (Theme.swift) on both sides of every inspector. The earlier attempts (alphabetical apps, footer in a `VStack`, navigation-only sidebar, `.contentMinSize`) were not the cause but are harmless and kept. Checked with real window captures of every screen.

## Things to know about this machine and toolchain

- Only the Command Line Tools are installed (27.0, Swift 6.4). With them:
  - SwiftPM does not pass the Swift Testing macro plugin path: use `scripts/test.sh`, not `swift test`.
  - In the macOS 27 SDK, SwiftUI's `@State` is a macro whose plugin ships only with Xcode: do not use `@State`; keep view state in `WindowState` (an `@Observable` owned by the app).
- `sfltool dumpbtm` shows an administrator password prompt when run as a normal user: never run it outside the helper.
- The app checks itself without screen recording through debug-only environment variables (`HECTOR_SNAPSHOT`, `HECTOR_DEBUG_HOVER`, `HECTOR_DEBUG_SELECT`, `HECTOR_DEBUG_SCREEN`); see CONTRIBUTING.md.
- Agent worktrees live under `.claude/worktrees/` (ignored by git). Once their branches are merged, remove them with `git worktree remove` and delete the branches.
